# 局部调色独立工作台实施计划

沿用用户已授权的独立Windows课程研究App、现有剪映式界面与自主测试流程，不修改稳定版或全局研究工作台。现有工作台依赖全局Mapping，直接复用会丢失空间关系，因此另建空间Store／Handler／导出管理器，保留既有上传、历史、强度、基础／HSL／曲线布局。

1. `spatial_store.py`：校验模型／代码身份，存储空间网格及独立数据；预览按归一化坐标渲染，缓存调色预览以支持快速强度变化；ICC-aware图片解码，手动调节在局部结果后执行。零强度保留调色前图。写测试验证缓存篡改和错误格式拒绝。
2. `spatial_jobs.py`：沿用任务状态／取消／原子发布，PNG保原尺寸，视频逐帧重新分析，首版明确30fps并保留可选音频；记录改帧率及编码损失。拒绝CUBE，不能以全局占位映射导出。
3. `spatial_workbench.py`：复用已有页面和控件，清楚标记非商业课程研究版、视频30fps；隐藏CUBE选项并在后端拒绝。预览、取色、导出使用同一局部路径。项目保存恢复校验模型与缓存，移除未实现功能的误导文案。
4. 新入口单独数据目录及端口，启动进程隐藏，保存PID/token/实例身份；关闭只停止拥有的服务。不得抢占现有工作台或更改用户最近工程。
5. 使用独立测试目录执行真实HTTP：上传、分析、强度0/50/100、手动调整、曲线取色、保存恢复、原尺寸PNG及视频帧率／音频／取消、CUBE拒绝、缓存与模型失效检查。记录接口端到端耗时；仅通过HTTP不声称界面视觉已验收。没有可用浏览器自动化时明确保留该限制。

工作台仍为研究原型。模型与数据仅允许非商业学术用途，不发布研究权重或素材。完整自然视频质量、强风格失败和独立模型泛化限制继续保留，不用UI接入代替效果验收。完成一套可演示里程碑后再整理Git，避免每个小变化远程上传。
