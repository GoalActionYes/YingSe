# 第7阶段：浏览器验收与强度回拉修复

本阶段改善13号研究版的实际操作，未训练或替换模型。13号仍使用已接入的多参考训练模型；稳定版1.3保持原有行为。本阶段不证明已经完整恢复剪映算法，也不证明参考风格迁移质量已经满足全部目标。

## 发现的问题与修复

在真实 Edge 无头浏览器中导入目标图和参考图，等待首次分析完成后，将强度从默认80向下调整，再回到80。此前页面会把「上一次服务器确认的参数」误当成「现在屏幕上的参数」：中间的小预览已覆盖原画面，回到80却跳过本地计算，只能等服务器返回。

修复后，每次本地预览成功更新图像，就清除这个过期的服务器显示标记。服务器最终响应仍优先，旧参数、旧素材和迟到的线程结果仍不能覆盖当前设置。普通强度混合和带手动微调的线程路径均增加了回归测试：两项在修复前失败，修复后通过。

使用入口保持为项目根目录下的 `00-从这里开始/13-打开自适应调色新版.cmd`。更新源码后重新启动13号入口，启动器会按构建标识检查服务版本；正在使用旧页面时需重新打开页面。本阶段不更改权重、参考分析、视频平滑或导出公式。

测试使用独立的本机服务、独立工程目录、全新浏览器上下文，不连接用户已打开的浏览器或覆盖用户工程。已有 Playwright Core 驱动 Edge 157.0.4341.46，视口1440×1000。未安装新工具。

延迟定义为浏览器触发控件 `input` 事件，到结果图片解码完成后的下一次 `requestAnimationFrame`。这不是鼠标硬件输入到显示器呈现的端到端延迟，也不是持续拖动帧率。测试逐步输入参数，未测所有设备、4K长视频或复杂HSL／曲线组合的持续拖动。截图已在本机查看，但无头浏览器验收不能替代用户的可见窗口体验。

测试器使用 Windows Job Object 包含自己启动的 Node 与浏览器进程；确认绑定后才允许启动浏览器。正常结束或超时均关闭该进程组，实际子进程清理测试通过。独立只读审查指出的超时清理问题已修复，未操作用户现有浏览器。

## 与整个目标的关系

这次解决的是「已有结果能否快速、正确地显示与导出」，没有增加模型的风格理解能力。现有软件已具备参考图＋目标图片／视频的完整操作链；人物与背景的语义对应、任意参考下的协调性以及更广泛的照片／视频质量仍未完成验收。此前未通过效果门槛的训练候选继续保留为研究记录，不进入软件。

下一步应围绕现有13号的实际输出，整理不同参考风格下的成功与失败案例，并检查视频变化是否协调；不能因为本阶段交互通过就宣布整体算法目标完成，也不直接再开一轮训练。
