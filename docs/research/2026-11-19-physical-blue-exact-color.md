# 实拍换灯的同色误差可复算，平坦区域覆盖不足

上一轮的全图 3×3 矩阵无法准确重现实拍蓝灯。这里允许任意精细的 RGB8 查表，对白灯原片中完全相同的 RGB 像素，只能给出同一个输出。对每个颜色组取实拍结果逐通道中位数，得到平均绝对误差的最小值。数字加蓝采用相同位置和规则。主域排除接近通道端点、局部高反差和外圈像素，要求一种颜色至少在两个图块中重复、合计至少四点。[事前协议](../../experimental/adaptive-reference-20261113/physical-blue-exact-color-protocol.md) · [原矩阵结果](2026-11-19-physical-blue-global-fit.md)

| Film A 关闭 | 平坦同色区域覆盖全图 | 实拍在该域的最小误差 | 数字加蓝的最小误差 |
| --- | ---: | ---: | ---: |
| 场景 1，灯强 213 | 8.60% | 1.366 | 0 |
| 场景 1，灯强 241 | 9.17% | 1.367 | 0 |
| 场景 2，灯强 213 | 7.28% | 1.397 | 0 |
| 场景 2，灯强 241 | 8.64% | 1.388 | 0 |

误差单位为 RGB8 码值。四组真实蓝灯均有无法由单值 RGB 查表消除的像素差，但主域覆盖都低于事前要求的 10%，联合必要条件为 0/4。全画面使用答案构造的最优查表误差为 1.08–1.15，低于原 3×3 矩阵在留出图块上的全图误差 4.69–4.84。两个数值使用的答案范围不同，不能把差值当作一个可泛化的改进。Film A 开启条件下，平坦同色覆盖为 3.97%–6.97%，实拍下界为 1.55–1.57，数字控制仍精确复现。[场景 1 对照](../../outputs/adaptive-reference-20261113/physical-blue-exact-color-v1/Scene1_a-241-comparison.png) · [场景 2 对照](../../outputs/adaptive-reference-20261113/physical-blue-exact-color-v1/Scene2_a-213-comparison.png)

普通 CUBE 对完全相同的输入 RGB 只能给出相同结果，因此有限范围内出现的同色冲突无法通过增加查表精度消除。这组样本不足以确认冲突来自可泛化的局部受光，量化、成像噪声及微小配准差也可能贡献误差。结束在这两组静物上把查表残差当成单图识别信号的尝试。若有新增真实数据，需用方向或材料分区已知的样本、同灯重复拍摄，以及非线性或局部的创意调色来检验。现有两图软件未使用这些答案或查表成片。

两遍各 16 张离线查表成片、四张图板及报告逐件匹配。另用 OpenCV 邻域核、按 RGB 分组和逐组中位数独立复算主域及最小误差，检查所有落盘成片的 RGB 单值性。以已有 NumPy、Pillow 环境执行 `probe_physical_blue_exact_color.py <本机研究输出根目录> <新输出目录>`。媒体和图板留本机。[复现脚本](../../experimental/adaptive-reference-20261113/probe_physical_blue_exact_color.py) · [数值与哈希](2026-11-19-physical-blue-exact-color-evidence.json)
