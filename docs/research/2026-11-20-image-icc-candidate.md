# 图片 ICC 解码候选

候选解决稳定工作台将有标签的 Display P3 像素直接当作 sRGB 使用的问题。支持的嵌入 RGB 配置按相对色度意图转换为 sRGB，然后进入既有分析、预览和导出。保留 8 位 SDR 校验和 EXIF 方向；未标记、损坏、不匹配或当前依赖无法处理的配置仍用原 Pillow RGB 兼容路径。这里不猜测未标记图片的色域，也不扩大视频/HDR 或宽色域输出的支持范围。

13 号实际工作台此前已有独立、严格的 ICC 转换。旧研究脚本为控制输入绕过了这个入口，因此显示的差异只能证明共用解码路径的缺口。候选保留 13 号旧的转换和不可用配置报错，调整验证调用避免重复转换。13 号启动签名纳入媒体解码文件。切换候选时，旧映射需要重新分析；有效旧项目的目标、参考、强度与手动参数照常恢复，再应用新分析。损坏或改动的素材继续报错。[原研究](2026-11-20-reference-icc-invariance.md)

## 启动与回退

在独立候选工作树根目录运行下列命令，用终端输出的本地地址打开稳定工作台。数据目录与现有稳定版隔离。

```powershell
& '.tools/vision-advisor-env/Scripts/python.exe' -m reference_color_app.server --data-dir 'dev-data/icc-stable-candidate'
```

候选复用已准备的本机 Python 和图像依赖。图片控制使用报告所列 Display P3 配置，配置的 CC0 测试字节在 HTTP 测试内，软件解码用户文件自己的标签，不读取该测试配置。13 号使用原研究环境与模型，可在候选工作树用既有 13 号入口或 `launch_spatial_workbench.py --multiref --check` 启动。回退时退出候选，回到原工作树的启动入口和对应原数据目录。原工作树的应用代码未切换，权重、既有项目与发布包均保留。

## 实际验证

- HTTP 回归先在旧解码复现 Display P3 像素不一致，再验证新解码。等价 sRGB／P3 的目标和参考经导入、原图预览、分析、调色预览和 PNG 导出，结果分别一致。损坏与颜色类型不匹配的 ICC 保留稳定版的原值读取。模拟旧分析缓存时，接口保留旧项目参数并要求重新分析，旧映射不能用于预览。
- 用稳定工作台启动命令对 9483 实拍目标和两种等价参考做完整 HTTP 工作流，开启同样的明度与 HSL 微调。相对原 sRGB 参考成片，P3 去标签时误差为 0.8551 RGB8，有 P3 标签时为 0.0259 RGB8。每一臂预览与 PNG 导出像素相同。实验输入为已有实拍和受控重编码文件。
- 93 项稳定版 Python 回归通过，涵盖图片格式、EXIF、缓存、低／高位深边界和导出。20 项空间工作台测试与 5 项增强测试通过。用实际启动的 13 号 HTTP 服务验证 P3／sRGB 导入、分析、预览与 PNG 一致，并确认历史严格 ICC 失败行为仍在。依赖原始冻结证据的测试在工作树接入已有本机测试素材后执行。
- 既有手动控制合成回归中，PNG 和全局 CUBE 结果最大误差均为 0，MP4 输出 48 帧／24 fps，保留音频。这是功能回归；完整视频时序、性能及空间效果仍须独立验收。空间调色仍按原边界导出 PNG 或 MP4，单个普通 CUBE 只能表达全局颜色映射。
- 另用正常 HTTP 路径导入 8 秒的 `source-motion.mp4` 与带标签 Display P3、等价 sRGB、去标签 P3 三种参考。固定分析帧时间 3 秒、80% 和明度 12。P3 与 sRGB 的预览 PNG 相同，完整导出的 192 张解码帧及时间轴相同。去标签参考产生不同输出，对照有辨别力。所有输出保有源帧数、时间戳及时间基，两次正式对照的预览和帧哈希一致。[视频验证脚本](../../scripts/probe_reference_icc_video.py)

视频对照使用 960 × 540、24 fps、无音频的既有合成运动片。两遍的分析请求约 1.00–1.04 秒，预览约 0.71–0.86 秒，提交导出到完成约 1.70–1.76 秒。导出时长包含排队、解码、应用 LUT、编码和程序的输出复核。单独用 FFmpeg 重读整个导出进行校验，不计入这些导出时间。各内部阶段未分开计时；这不是独立的推理或渲染速度。没有真实遮挡、切镜、时序色彩稳定性或自然评价结论。

复现时在候选根目录设置 `PYTHONPATH`，用已有视觉环境运行 `scripts/probe_reference_icc_video.py <原运动视频> <带标签 P3 原参考> <新输出目录>`。视频 SHA256 为 `ed5095191a8c5f142e59f8fc5807ba3a35c8dd0eff05b45c57f65b7bf03ca759`，参考 SHA256 为 `c1634e0f981bf62874c8d9581c5f6920d5b52c97876caf5071d76273a12bdd02`。本机记录在 `outputs/image-icc-candidate-video-v2`，媒体不随 Git 分发。

补充测试三张 WebKit 原始 JPEG，涵盖两份不同 Display P3 配置及一份 Adobe RGB (1998)。每张分别作目标和参考，六项带标签成片均与按标签转换的 sRGB 基准逐像素一致。本机外部 JPEG 验证与自制样张结果参考[第三方 JPEG 验证](2026-11-20-external-icc-jpeg.md)。

候选尚未合并或替换现有版本。未做跨场景独立画质及自然度评价。本机原对照输出位于 `outputs/image-icc-candidate-real`。阶段标记为图片解码工程修复，不能当作自动调色主目标通过。
