# 13 号工作台的视频完整导出与分段耗时

使用普通 HTTP 导入、分析和 MP4 导出，对 13 号现有流程建立可复查的性能基线。两段都是已用开发素材，尺寸 640×360、时长约 3 秒，一段含人物运动，一段带音轨。两臂固定参考、同一 multiref 检查点、80% 强度和既有时序平滑。每臂另建本机数据目录。计时包装仅在验证脚本进程内生效。[事前协议](../../experimental/adaptive-reference-20261113/spatial-video-stage-timing-protocol.md) · [原逐帧测试](2026-11-13-spatial-native-video.md)

| 环节 | 正式两遍、两片范围（秒） | 口径 |
| --- | ---: | --- |
| 分析请求 | 0.62–0.92 | 上传后发起分析至 HTTP 返回，含相关校验与首帧读取 |
| 普通完整导出 | 3.08–3.42 | 请求提交至完成，含实际解码、逐帧处理、编码与输出检查 |
| 带测点完整导出 | 3.29–3.53 | 同上，客户端轮询间隔 50 毫秒 |
| 导出工作线程 | 3.02–3.30 | 在后台工作线程计时，包含建立管道和结果发布 |
| 工作线程初始素材解码 | 0.145–0.154 | 目标首帧和参考的读取及相关探测 |
| FFmpeg 解码管道读取 | 0.073–0.084 | 父进程读帧的阻塞和传输时间 |
| 逐帧输入准备 | 0.446–0.467 | 目标及参考的缩放和 GPU 上传，包含在网格准备内 |
| 逐帧空间网格准备 | 1.064–1.149 | 包含输入准备、统计、模型推理和同步 |
| 网格模型 GPU 推理 | 0.446–0.489 | CUDA 事件测量，仅网格模型调用，包含在上一项内 |
| 空间调色渲染 | 0.770–0.856 | 网格对原尺寸帧的变换与读回 |
| 强度混合和收尾 | 0.566–0.655 | 与原帧混合、调整合并、RGB8 输出 |
| FFmpeg 编码管道和收尾 | 0.068–0.087 | 父进程写帧、关闭管道及等待编码结束 |
| 导出后独立解码复核 | 0.139–0.146 | 带测点两片两遍，不计入任何完整导出值 |

环境为 Intel Core i9-13900HX、RTX 4060 Laptop GPU。编解码器与逐帧处理重叠，管道等待无法换算为编解码器的独占 CPU 时间。网格事件与空间准备有包含关系，不应累加。正式两遍的每条导出均为 90 帧、30 fps、640×360。有声片生成 130 个解码音频块，无声片没有音轨。分别重读全部八个输出，两个视频各自的所有帧、音轨和时间戳哈希在计时和无计时两臂及两遍之间一致。独立确认输入以 30 fps 重采样也是 90 帧。

首轮写错参考哈希，在启动工作台前被校验拦截。按本机素材实际哈希修正后，完成试跑和两次正式导出。未改工作台本身、权重、时间平滑或输出设置。这份记录用于今后比较候选的端到端成本。它未测量真实遮挡、切镜下的颜色稳定性或新候选的画质收益。

## 复现

在已有视觉环境设置仓库根目录为 `PYTHONPATH`、`OPENBLAS_NUM_THREADS=2`。运行 `python experimental/adaptive-reference-20261113/probe_spatial_video_stage_timing.py outputs <新输出目录>`，脚本会核对两个视频、参考和模型的哈希。两次正式报告 SHA256 分别为 `883b8f0bd6247173b6a83ec3d5a154ce968163624ce6f380575147ad24e5a0fb`、`9df6afcfcf6f93271a8d06e6b58fb39044cb25f82ed93fdf3346333515b7325a`。时间随机器状态变化，音视频帧哈希可比较。媒体和完整运行目录留本机。[本机耗时和成片](../../outputs/adaptive-reference-20261113/spatial-video-stage-timing-v2) · [复现脚本](../../experimental/adaptive-reference-20261113/probe_spatial_video_stage_timing.py)
