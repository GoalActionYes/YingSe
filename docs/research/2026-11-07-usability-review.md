# 1.3 使用评估：让试错可恢复

本轮按用户要求，以实际使用任务评估现有软件，而非继续堆控件。范围是手动微调的撤销与重做，既有交互缩略预览、曲线取色和导出计算保持原样。

## 发现与解决

| 任务／问题 | 处理与结果 |
| --- | --- |
| 改了参数或误点重置后想回去 | 增加撤销微调／重做，基础、HSL、曲线、分组开关和重置均纳入历史 |
| 一次拖动产生很多中间数值 | 同一手势合并成一步；数值编辑按焦点会话合并；最多 50 步 |
| 只点滑块不改值，或指针取消 | 审查发现分组可能未结束，补齐 pointerup／cancel／lost capture 处理 |
| 焦点在分组开关，快捷键失效 | 修正文本编辑判断，开关可使用全局撤销；输入框仍保留原生文字撤销 |
| 拖回起点仍出现无意义历史 | 同一手势回到起值时不留空步骤 |
| 撤销后画面／保存／导出脱节 | 复用现有参数变化通知，清除过期取色标记，更新预览、保存和导出失效状态 |

实际便携浏览器中验证：载入示例 → 色温 30 → 重置全部 → 撤销恢复 30 → 重做归零 → 再撤销 → 关闭基础分组 → 在开关焦点下 Ctrl+Z 恢复。面板数值、按钮状态和预览通知符合预期。

自动检查：77 项 Python 源码检查、9 项 Node 检查通过。历史测试覆盖分组、分支、快照隔离、上限、重载基线和空手势；已有取色、预览竞争与恢复检查仍通过。独立审查指出的两个问题均修复。便携 EXE 启动、重启、三格式导出及异常依赖检查通过。

## 明确边界

撤销只管理手动微调，不撤销素材导入、克隆强度或参考图分析。快捷键 Ctrl+Z、Ctrl+Y／Ctrl+Shift+Z；Mac 浏览器也接受 Command 修饰键。输入框内优先原生编辑。重启不保留撤销栈，恢复的参数成为新基线；换素材或分析帧时重新建立历史。历史不是完整工程版本管理。

本批没有证明软件已尽善尽美。仍需继续评估：

- 不同便携版本间的用户工程迁移；当前包的 data 相互独立，旧包与数据保留，不能当成已自动迁移。
- 多机器和更复杂视频上的端到端延迟；1.2 的单机大图实测不能代替普遍性能保证。
- 原图缩略预览与全尺寸导出的细节差异、独立自然素材的主观质量，以及新同学无指导使用。
- 现阶段仍以“参考图匹配后微调”为主，未支持无参考图的完整独立调色流程。

验收记录与便携包校验值见 usability-history-verification.json。下一阶段按实际影响排序处理这些问题，不把新增页签数量当成成熟度指标。
