# 自适应参考调色新版：使用与验证

本机入口：`00-从这里开始/13-打开自适应调色新版.cmd`。这是独立课程研究工作台，使用通过新32图完整门槛的多参考监督模型，视频自动平滑颜色网格。主程序和12号旧模型入口仍保留，不是完整剪映算法复刻。

后续已增加[强度连续预览](2026-11-13-strength-preview.md)：默认微调下先在页面内响应，后端最终确认。用户反馈能连续更新、比较跟手；不代表所有微调控件或实际浏览器帧率都已验证。

## 怎么体验

1. 双击13号入口；启动器打印并打开本次本地地址，重复双击复用同一服务。
2. 导入目标图片或视频，选择一张参考图，等待分析。已有基础、HSL、曲线、取色和撤销等操作继续保留。
3. 调整强度或关闭色彩克隆比较原色；手动微调独立生效，关闭克隆不会关闭微调。
4. 图片选PNG，视频选MP4。视频保留首条可用音轨，以30fps导出，奇数边补齐偶数。空间自适应不能完整保存为普通CUBE；需要全局CUBE对照时使用11号入口。

首次本机体验已准备一份测试示例。它只保存在本机，不是随Git分发的内置素材。可直接换成自己的参考和目标。

## 本版增加什么

| 部分 | 具体行为 |
|---|---|
| 调色模型 | 固定多参考普通监督第6轮，SHA `d8d8e6727a44100e6fedb11b605a17e33afc675de7448d4ebcf6d24d492ad4c9`；不用失败的额外配对损失模型 |
| 视频 | 每帧自适应后做固定系数平滑，大变化重置；每次导出独立状态 |
| 强度与手动微调 | 图片、预览、视频统一为满强度RGB结果→强度混合→手动微调，修复旧研究视频在边界颜色上的不同混合顺序 |
| 工程 | 新版使用`dev-data/spatial-multiref`，旧12号使用`dev-data/spatial-reference`；模型变化时旧网格失效，素材和操作参数可恢复后重新分析 |
| 启动 | 校验目录、PID、版本标识及代码版本；不会复用其他版本的服务，有导出时拒绝强行关闭 |

默认研究引擎及12号仍使用App8权重；本次强度处理顺序的修复适用于两种研究配置。稳定版`reference_color_app`没有改动。

## 实际验证

在隔离目录通过真实GPU／HTTP完成：

- 1920×1080 PNG与服务端渲染逐像素一致，零强度保持原色，基础微调和曲线取色可用。
- 640×360短片输出90帧／30fps；含音轨的半强度＋亮度／对比度导出成功。抽样帧与独立顺序渲染、混合及微调基准的平均差约1.7–1.9码值，包含H.264／YUV420有损误差。
- 导出期间关闭请求被拒绝；取消正在运行的导出后，无结果文件或临时输出残留。
- 真实2160×3840素材的短段有声导出、输入CFR与实际输出解码帧数核对；完整原素材预览和导出期间预览均有记录。
- 实际进程重启、两个启动器同时启动及再次复用；素材、强度、微调恢复，重启前后预览相同。源码更新后的失效网格另做恢复检查。

首次HTTP运行较慢，后续完整工作流的温缓存预览约0.13–0.15秒；4K原素材运行受环境状态影响更明显，不能把小图结果推广为所有输入的固定响应时间。4K导出仍是离线处理，未达到实时视频编码。详细数值以[本阶段证据](2026-11-13-multiref-workbench-evidence.json)为准。

## 边界和待完成项

静帧预览没有之前所有帧的平滑历史；所测短片第1秒与成片压缩前平均差约0.40码值，不保证所有视频都这么小。界面已提示视频成片与单帧预览可能略有差异。不是逐帧预览／成片严格一致的声明。

本机没有可用的浏览器／桌面控制运行接口，因此已验证HTTP和源代码交互逻辑，尚未完成实际拖动、布局和视觉操作验收。应用内浏览器打开请求不等于确认界面显示正常。

仍需完善控件响应和拖动体验、更多自然切镜、音画同步的主观检查及不同参考的自然度；不能凭32图门槛与一条运动片宣称普遍理解人物／背景。本模型仍不读取参考图的空间语义布局，强风格参考也可能迁移不足。[算法和独立验证限制](2026-11-13-multiref-independent.md)继续适用。

所有输入／输出均限既有RGB8研究处理链，10位SDR兼容输入会转换，不是10位／16位保真。Git不包含环境、权重、原图或会话，其他电脑不能仅克隆就运行13号；研究用途限课程／非商业范围，稳定开发版按[源码指南](../GETTING_STARTED.md)准备。
