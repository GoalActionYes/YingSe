# 目标空间编码只看亮度，背景偏色仍保留

13 号一边使用目标与参考的整图颜色直方图，一边用目标低分辨率 RGB 预测各处的颜色变换。本轮只将空间编码器送入的 64×64 RGB 变为亮度。直方图、模型权重、网格滤波、原始彩色目标渲染、80% 混合均保持相同。原 RGB 路径逐像素复现 62 张冻结基线。见[事前协议](../../experimental/adaptive-reference-20261113/target-spatial-chroma-protocol.md)。

| 检查 | 空间编码只看亮度 | 原门槛 |
| --- | ---: | ---: |
| 人物抗背景干扰且保留整图着色 | 0/8 | ≥6/8 |
| 近中性色背景干扰降幅 | 0.53% | ≥15% |
| 对比度与去饱和响应 | 8/12 | 12/12 |
| 局部背景冷色与人物保护 | 0/4 | ≥3/4 |
| 整图冷色与无人负例 | 2/6、2/2 | ≥4/6、2/2 |
| PSBench 台阶／铁塔 | 0/2 | 至少一向改善 |

空间编码输入改变后，各输出对 13 号的 RGB 平均绝对差再取全批平均为 4.04 码值，最大单图值 8.06。目标颜色确实影响网格与出图。白球服参考背景变品红时，目标近中性色的变化由 9.91 到 9.59，偏色仍明显。有意局部冷色的白球服人物近中性色误差由 5.47 到 5.26。两组 PSBench 实图整图误差均增大，铁塔为 15.03 → 17.41，台阶人像为 15.46 → 16.17。画面对照留在本机 `target-spatial-color-comparison.png`。

两遍各 62 张输出一致，用时 9.24、9.45 秒，另从保存的 PNG 独立复核 166 项变化量、计数和近中性色度量。同图保持通过。两张输入仍是常规照片，内部只改变一条输入路径，没有在评分时向模型提供区域或作者答案。见[数值与身份](2026-11-18-target-spatial-chroma-evidence.json)。

结束冻结模型的直接灰度替换。该结果只说明用亮度直接替换原有编码器输入，无法避免这组跨场景偏色。由于灰度是冻结模型的分布外输入，本轮没有测试专门训练的亮度模型。当前未得到可接入的软件改进，也未读取独立保留素材。

复现时在仓库根目录设置 `$env:PYTHONPATH = (Get-Location).Path` 与 `$env:OPENBLAS_NUM_THREADS = '2'`，用现有研究 Python 运行 `experimental/adaptive-reference-20261113/probe_target_spatial_chroma.py <新输出目录>`。需要本机固定 13 号及现有三套开发对照。完整输出保存在 `outputs/adaptive-reference-20261113/target-spatial-chroma-v1` 与对应重复目录。
