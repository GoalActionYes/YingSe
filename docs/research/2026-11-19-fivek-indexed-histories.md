# FiveK 找到跨原文件的同一项对比度操作

用 Lightroom 目录的 `(image, dateCreated)` 索引读取完整历史，逐项核对索引与历史表。按图像键头尾各取四个，头部四个图像版本都属于同一原文件，尾部四组虽对应四个其它原文件，却均没有单项颜色记录。区别原片与虚拟版本后，这八个版本只对应五份原文件，未找到跨文件同操作。[上轮目录证据](2026-11-19-fivek-history-pages.md) · [本轮协议](../../experimental/adaptive-reference-20261113/fivek-indexed-histories-protocol.md) · [SQLite 索引格式](https://www.sqlite.org/fileformat.html)

再用目录的原文件索引抽样。固定前四个原文件、每文件最多六个版本。预算内查完整了 16/24 个版本，覆盖三个原文件，包含 177 条可解析状态与 161 对相邻状态。其余八个版本登记为页未读取，保留同一预算上限。两次抽样合计新增 380,928 字节数据库页，没有下载照片或完整目录。

查到一组跨原文件的匹配。两张照片的目录拍摄日期不同，作者各有一步仅改变 `Contrast`，且起止值相同，变化量为 **+13**。两组历史状态之间仍有 14 项不同字段，包括曝光、色温和色调。因此保存为「同一对比度操作作用于不同起始状态」的复原候选。没有发现满足本轮精确规则的跨原文件单项曝光、饱和度或局部操作配对。现有抽样只支持所读版本的结论。[摘要与页哈希](2026-11-19-fivek-indexed-histories-evidence.json)

下阶段可以用这对历史验证同一对比度操作的明暗响应，条件是拿到对应原片并核实旧处理版本能逐状态复原。需检查目标自然颜色以及同款参考更换时输出是否稳定。此次没有生成这两个历史状态的像素，不能量化调色迁移，也没有找到可独立打分的肤色、白墙或局部颜色样本。原片的最终独立评估资格没有变动。

复制本机页缓存，用 `audit_fivek_indexed_histories.py <报告 JSON> <本机页目录> --offline` 重算图像索引，再加 `--by-file` 重算原文件抽样。数据源编号和时间仅在本机运行时使用。两遍原文件报告逐字节一致，更新索引读法后上轮目录摘要仍可复现。用 SQLite 的 12,500 行合成库独立核对整个索引、倒序及指定首键。首次加拍摄日比对时变量遮蔽导致离线运行退出，修正后使用原缓存连续复核，未产生新 HTTP 请求。[脚本](../../experimental/adaptive-reference-20261113/audit_fivek_indexed_histories.py)
