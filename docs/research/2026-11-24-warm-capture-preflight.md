# 第一组暖白灯补拍的本机预检

当前只用一张普通参考和目标时，现有工作台既漏掉浅墙的局部暖色，也会把现场光色传到人脸。跨来源暖色比较缺一组幅度相当的可追溯实拍。前一轮 LSMI 的场景 931 已通过方向，但编辑幅度只有真实换灯的 43.7%。LightMove-A 公布的成片缺逐对曝光和共同显影记录。补拍前先提供一个可以在第一组量出灯光变化幅度的入口，减少拍完三组才发现条件不合适的返工。[旧工作台](2026-11-24-matched-wall-warmth-workbench.md) · [LSMI](2026-11-24-lsmi-daylight-switch.md) · [LightMove-A](2026-11-24-lightmove-a-intake.md)

新增一个研究命令。给它两张只改变登记灯档、未加局部编辑的 SDR 小样、同组拍摄记录、一块浅色测区和至少一块保护区。临时显影采用已有 RGB8 sRGB 输入策略。先检查尺寸、同图重复、测区边界和原位梯度配准，再用冻结 RawTherapee 配置自动导出两档各自的开与关。生成一份现有初检能读取的四图目录，保留固定处理设置、原位比较报告和数值摘要。每个方向沿用既有通道端点、保护区和联合门槛。报告分别列出过线的方向、未过线项和幅度比。实际灯具、曝光、白平衡、固定材质、地标及是否遮挡仍按拍摄记录人工核实。

两处既有依赖是补样的四图目录及文件初检，以及冻结的 RawTherapee 出图和暖色准入评分。沿用既有输入色彩转换和原位梯度筛查。实现阶段依次验证参数和错误分支、接上已有渲染函数、验证实际导出和本机交接说明。常规产品入口和研究基线继续照常工作。从两组已有结果验证接入，不重做来源调查或更改门槛。应重现 MIT 复印室 8 到 0 的数值匹配，并保持 LSMI 931 的 12 到 13 在方向通过且幅度失败。每组跑两遍核对成片文件与报告。首次准备和核验 30–45 分钟，现有环境，本机渲染预算 4 分钟，无训练。预检仅决定补拍灯档是否值得继续。只有实际新增独立来源的原片、拍摄记录、四图门槛都通过，才计入后续开发数据。

## 拍第一组时怎么用

先固定相机、焦距、主体、底光和白平衡。记录相机、快门、光圈、ISO、白平衡、补光灯档及素材用途。让暖白灯在浅墙上产生小幅变化，墙面之外保留一块同样可见、应该不受局部编辑影响的材料。两档都保留原件，并用同一固定设置导出同尺寸的 RGB8 sRGB JPG 或 PNG。试拍可先按长边约 1500 像素导出，两档保持同样的处理设置。原始 RAW 和相机设置留本机。

打开基准图 A，选一块无明显反光、暗角和遮挡的浅色区域。记录左、上、右、下四个像素坐标，左上角为原点，右和下为不含边界的坐标。另记至少一块远离编辑区的保护区。先固定这些坐标和测区旁两个可定位的地标，再查看 B。两图中地标、材料和遮挡都应保持一致。补光档位要改变时，保持已定编辑、测区和保护区。每个新档另存原件和报告，便于追查前后差异。

在项目根目录执行以下 PowerShell。输入文件和拍摄记录路径换成本机实际值。下面的坐标是 MIT 复印室的示例，补拍时用上一步测得的坐标。V 盘临时映射让 RawTherapee 使用 ASCII 路径，命令完成后解除。输出请使用一个新的目录。

~~~powershell
if (Test-Path 'V:\') { throw 'V: already in use' }
subst.exe V: (Get-Location).Path
try {
    $env:PYTHONPATH = 'V:/;V:/.tools/tf-convert-env/Lib/site-packages'
    $env:OPENBLAS_NUM_THREADS = '2'
    & V:/.tools/adaptive-env/Scripts/python.exe V:/experimental/adaptive-reference-20261113/warm_capture_preflight.py `
        'E:/本机补样/基准光.png' 'E:/本机补样/暖白灯.png' 'E:/本机补样/capture.md' `
        'V:/outputs/adaptive-reference-20261113/warm-capture-pilot-01' `
        --edit 192 462 330 552 --guard 1212 186 1278 315 --guard 333 858 372 894
    if ($LASTEXITCODE -ne 0) { throw "Warm-light preflight returned $LASTEXITCODE" }
} finally {
    subst.exe V: /D
}
~~~

打开结果目录里的 `results.json`。它列出两档开关各自的覆盖、端点和保护区读数，以及两个方向的联合门槛。命令退出 0 表示成功生成报告，灯档是否匹配看 `matching_directions`。若素材、覆盖和颜色方向都过线，`ratio` 小于 0.75 表示现场变化偏强，可以在下一次实拍减小灯档差。大于 1.25 表示现场变化偏弱。若颜色方向也偏离，先复核光源色温和测区，幅度比不能单独用于选档。

`render/comparison.png` 存放实际导出的四张开关对照。`materials/first-pair` 可直接用旧初检复查，`render/` 里的两份 PP3 完整保留开关设置。报告要求继续人工核对曝光、白平衡、同一材质、两处地标和用途。整图没有检测到位移仍可能有局部移位。以冻结测试验证了这一限制。全部媒体和拍摄记录保留本机。[四图交接要求](2026-11-21-capture-edit-intake.md) · [EGM 审阅](../../outputs/adaptive-reference-20261113/warm-capture-preflight-egm.md) · [研究命令](../../experimental/adaptive-reference-20261113/warm_capture_preflight.py)

## 已验证结果

三组均使用先前留在本机的固定实拍。按文档的 Windows 命令分别生成两遍，每次从 Python 启动到报告写完为 4.75–8.63 秒。每组两遍的 11 张 PNG、2 份 PP3 和 1 份 JSON 逐文件一致。生成的四图与相应旧研究成片的 SHA-256 相同。两档双向的变化向量、方向和幅度从落盘图独立复算，共六个方向。五个自动测试覆盖重复、尺寸、区域边界、无纹理和整体移位，还复现了整图配准无法拦截的小范围移位。首次重复时暴露了报告里脚本哈希的路径类型错误，改用 Path 后重跑了全部三组。[结构化证据](2026-11-24-warm-capture-preflight-evidence.json)

| 冻结对照 | 第一方向结果 | 实际判定 |
| --- | --- | --- |
| MIT 复印室 8 → 0 | 余弦 0.924，幅度比 0.952 | 匹配。反方向的颜色方向未过线。 |
| LSMI 931 的 12 → 13 | 余弦 0.935，幅度比 0.437 | 现场光变化过强。 |
| LSMI 938 的 12 → 13 | 变动光有效覆盖为 0%，四图齐全 | 拒绝出图数据用于暖色匹配，方向和幅度无有效读数。 |
