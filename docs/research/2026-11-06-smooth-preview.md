# 1.1.1 预览流畅度改进

目标：现有控件拖动时持续反馈，减少同一帧重复解码，失败时不清空画面。用户已授权自行实现、使用与测试，无需逐项审批。本批是现有流程的集中修复，不增加色轮或改变颜色算法。

## 改动

- 手动调整由停下 160 ms 才更新，改为每 120 ms 调度最新状态。克隆强度沿用相同调度，短时间重复输入合并；网络请求仍串行，避免堆积。
- 同一目标和分析时间的近期解码帧与原图 PNG 可复用；最多两项，像素和编码文本合计预算 32 MiB。超预算的单帧不缓存，仍正常处理；预算不代表整个进程的内存上限。
- 每次查询仍校验素材完整性，缓存不绕过原有验证，不缓存导出画面。
- 失败保留最后一张成功画面，并明确显示“预览未更新”；过时的参数、映射或素材请求错误不覆盖当前状态。

## 验证

先观察新增 Python 缓存测试因缺模块失败，前端调度与保留画面测试失败，再实现并重跑通过。最终 76 项源码检查、5 项前端检查通过；独立代码审查无待修问题。

实际 HTTP 两次不同强度预览仅解码一次，原图 PNG 相同；已有缓存时，素材校验失败仍返回错误。缓存测试覆盖淘汰、内存预算、大帧不保留和加载失败。

在新便携包浏览器中连续输入色温 10、-15、30，确认最后为 30，预览更新并保存。便携 EXE 生命周期、PNG／MP4／CUBE 导出核验通过；导出哈希与 1.1 相应控制样例一致，颜色处理不变。

这不是 60 fps 实时调色保证，尚未做多机器性能评测。大图依然有素材校验、颜色计算、PNG 编码和传输成本；仅证明调度行为和缓存复用，不虚构加速比例。正式便携包与 ZIP 校验值见同目录的 smooth-preview-verification.json。
