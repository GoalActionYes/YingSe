# 四图补样操作与本机初检

## 公开曝光素材补查

这次优先找能省掉拍摄的公开曝光组。Cambridge 发布真实多曝光 RAW／JPEG 及配准验证用的参考组，作者用途是 HDR 重建和去重影。easyHDR 图廊展示实际包围曝光和作者有意调色，也提供一个示例工程。页面说明它先把多张照片合成一张 HDR，再做创意处理，没有逐档单独开和关同一编辑的输出。Aaron Rust 的 CC0 样例包含 28 个 RAW 及 Lightroom 开发的 HDR、SDR 和参数截图，作者说明的是每张原片的多种导出；未在作者说明中确认同内容存在两档实拍光线交叉。三条来源均未取得联合小样资格。包围曝光也不能当作真实换灯。没有下载图片或大型归档。[Cambridge 数据说明](https://www.repository.cam.ac.uk/items/b65f07c4-a4f5-4310-b5ec-a1c27fd52d6a) · [easyHDR 图廊示例](https://www.easyhdr.com/examples/) · [Aaron Rust 的素材及开发说明](https://github.com/aaron-rust/hdr-sample-images)

## 一组材料怎样拍和交接

用现有相机或能锁定参数的手机。在一块浅色背景前固定机位和主体位置。先确定基准光 A，锁定曝光、白平衡与焦距，再只改变准备记录的光源条件拍 B。A 和 B 各自保存原件。有条件时加一张同灯复拍，便于发现动作或相机处理变化。灰卡可以用来核对两次实际变化，已有可识别的同一块浅色表面也可先放入可行性小样。

对 A、B 分别开关**同一项可追溯的编辑**。例如，在两档中都只给脸部增加少量暖色，记录用的工具、参数以及大致生效位置，保持其他步骤一致。避免顺手裁切、磨皮或换色域。导出四份同尺寸 SDR 图作为检查副本，原文件和工程保留在本机。可先做三组不同人物或场景，预计拍摄 60–90 分钟，编辑与导出 1–2 小时。三组用于初筛能否取得所需证据，后续训练规模和正式验收另定。[上次资格及耗时判断](2026-11-21-capture-edit-feasibility.md)

在专用本机目录里，每个原始拍摄组占一个文件夹。组名用编号。原始相机文件无须改名，把导出的四份检查副本按下表命名，扩展名可用 JPEG、PNG 或 TIFF。

| 检查文件名主干 | 内容 |
| --- | --- |
| `light-a-before` | 基准光 A，关闭待测编辑 |
| `light-a-after` | 基准光 A，开启待测编辑 |
| `light-b-before` | 改变光源 B，关闭待测编辑 |
| `light-b-after` | 改变光源 B，开启待测编辑 |

同一组再留两份简短记录。两份可用几行普通文字，保留已经有的具体记录即可。

- `capture.md` 记录同组依据、变动的灯光、锁定的相机设置，以及这些照片可用于哪些范围。本地可另留原件定位和同灯复拍。
- `edit.md` 记录编辑软件、同一开关项、调整范围和参数，或指向组内项目文件／设置侧车。

## 收到材料后先核对什么

在项目根目录用现有研究 Python 运行以下命令，最后的目录换成实际的小样目录。报告留本机。

~~~powershell
& .tools/vision-advisor-env/Scripts/python.exe experimental/adaptive-reference-20261113/audit_capture_edit_pairs.py 'E:/本机补样目录'
~~~

脚本只检查目录内的四份可解码图、方向校正后尺寸、原文件哈希、转换为 RGB 后的精确重复像素和两份文字是否存在。再由项目侧检查来源许可、姿态和构图、实际灯光差、编辑是否同款及其作用范围，含同来源原图和导出变体的归组。初检无法发现经过重压缩或裁切的近重复，也不能判断灯光或作者编辑是真是假。文件齐备仅意味着可以做人工核验。

本机用合成色块验证了完整组、缺图和说明、损坏图片、尺寸不一致、同角色重复文件、不同字节但同像素的跨组重复，以及空目录。七个条件均得到预期退出状态，每项复跑输出一致。合成色块没有作为摄影素材或训练样本。当前仍缺真实联合小样，未启动训练，现有演示入口可继续使用。
