# 1.2 大图交互预览与曲线取色

用户报告色温改变后等待五六秒，要求修复并增加曲线取色定位。本批按已有自主实施授权推进，先定位耗时，再实现与验证。

## 原因与实测

此前缓存只减少解码，而预览仍对原尺寸图片着色后再缩放。4000×3000 控制像素单次着色约 6.907 秒；960×640 同类着色约 0.350 秒，组合 LUT 约 0.136 秒。

同一张 4000×3000 合成 PNG 的实际 HTTP 预览：旧路径 8.301 秒；新交互路径首次 0.924 秒，再次 0.763、0.708 秒。只有一台机器和一个控制样例，不当作所有素材的性能保证。原始数据见 interactive-picker-verification.json。

浏览器显式请求交互预览，先按最大 960×640 缩放，再执行同一组合映射。缓存键区分两种路径，旧客户端默认保持原路径。PNG、MP4 与 CUBE 导出不改，仍处理原尺寸或原有 LUT。缩放与非线性颜色变换次序不同，交互缩略图不保证与全尺寸导出缩略后逐像素相等，尤其是细碎纹理和高反差边缘。

## 曲线取色

曲线页点击“从画面取色定位”，再点击画面。按 object-fit:contain 的真实显示区域换算原图坐标，黑边不取色；读取选定分析帧的原始像素，计算克隆、基础、HSL 之后、曲线之前的输入。

RGB 曲线以三个颜色环标出三个输入，R/G/B 通道则先经过总 RGB 曲线，再显示对应通道位置。标记不是控制点，取色不更改调色。参数、克隆强度或素材变化后清除标记；过时请求不覆盖最新取色。取色为浮点分析，不把屏幕截图颜色当作曲线输入。

## 验证与限制

- 77 项 Python 源码检查、6 项 Node 检查通过。包含负数／越界／布尔坐标拒绝、曲线顺序、交互缩放尺寸、横竖图和黑边坐标换算、未加载图片等条件。
- 便携 EXE 三格式带微调导出、启动复用、重启、缺依赖等核验通过。
- 实际浏览器载入示例，点击色块后显示原图像素与输入 RGB，切换 R 通道标记正确；点击黑边无变化，未增加曲线控制点。
- 独立审查发现强度变化后的标记失效处理与过时取色错误处理不足，已补齐。

仍有素材完整性校验、解码、LUT 合成、编码与传输成本，不承诺 60 fps 实时预览或所有视频均低于一秒。取色针对单个像素，无区域平均；视频取的是当前分析帧，不是播放中任意时刻。
