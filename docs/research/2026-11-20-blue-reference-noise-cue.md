# 单图噪声线索在压缩和缩放后失效

已有白点开关把有意调成蓝色的参考当成蓝灯实拍。这轮只用单张参考，从较平坦区域测量蓝、绿通道的高频波动，检验能否区分这两种输入。依据是理想线性传感器中光子噪声随信号变化的规律。普通图片的高频信号还受纹理、相机处理及编码影响。用独立泊松样本验证方向，数字增益与实拍光量变化的读数差在编码前为 0.625，转成 sRGB8 后只有 0.037，低于预设的 0.25。[事前协议](../../experimental/adaptive-reference-20261113/blue-reference-noise-cue-protocol.md) · [原始传感器噪声论文](https://webpages.tuni.fi/foi/papers/Foi-PoissonianGaussianClippedRaw-2007-IEEE_TIP.pdf)

| 同一阈值下的参考格式 | 实拍蓝灯判对 | 程序加蓝判对 |
| --- | ---: | ---: |
| 原样 PNG | 8/8 | 8/8 |
| JPEG 90，4:2:0 | 8/8 | 0/8 |
| 双线性缩至 75% | 8/8 | 0/8 |

每次整场景留出，两场景采用相同相机来源，共检查 16 张有 Film A 开与关的蓝色参考。压缩或缩小后，数字蓝调全部落到「实拍蓝灯」一侧，用来触发校正会重现此前的错误方向。该范围只覆盖程序通道增益负例和两个无人场景，无法给出真人或多种创意调色的正确率。

为检查区分是否由执行数字增益前的一次额外 sRGB8 量化引起，保留同一线性 RGB8 原始文件、缩放方式和增益，仅把 sRGB8 量化移到增益之后。四张成片全图平均 RGB 差为 0.204–0.223 码值。四张都保持「数字加蓝」判断，读数平均下降只有原两类差值的 1.4%。额外的这一轮 sRGB8 量化无法解释原样 PNG 的分离，来源仍未确定。排除固定噪声阈值作为自动校正开关，本轮止于参考检验。

复现使用已装 OpenCV、NumPy 和 Pillow 的本机 `tf-convert-env`，运行 `probe_blue_reference_noise_cue.py <研究输出根目录> <新输出目录>`。最初因 8 位合成正控失败而退出，保留原门槛后补记浮点对照。初次编码对照先遇到视觉环境缺少 OpenCV，再由既有采集记录核实发布文件为线性 RGB8，按实际位深运行。两遍四张成片和报告均同哈希，复算落盘成片的误差和读数，确认加入控制前后的 48 项真实参考读数及决定一致。本机目录为 `outputs/adaptive-reference-20261113/blue-reference-noise-cue-v3`，报告 SHA256 为 `81b4188619062568d1b9c3c7aa2697b17be94863e6e6d2c996361794990c1d04`。软件和独立验收均未改变。
