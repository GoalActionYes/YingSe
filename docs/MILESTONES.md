# 映色：阶段成果与汇报记录

每次完成一个可体验、可验证的改进，再提交并推送研究分支，不按零碎修改刷版本。记录统一包含：原来的问题、采用的方法、现在能看到的效果、验证依据和剩余限制。稳定开发版1.3与这些研究阶段分开编号。

## 发布与汇报约定

每完成一个可验收的功能或效果改进，就整理成一个阶段提交，并推送 GitHub 研究分支，附可定位的阶段标记。日常修补可以保留本地提交；未形成完整成果时，不反复推送零碎变化。

每个阶段固定记录以下内容，供同学接手和课堂汇报使用：

| 项目 | 要说明的内容 |
|---|---|
| 用户问题 | 哪个操作不好用，或哪种调色结果不理想 |
| 实现方法 | 修改了哪个处理环节，解决问题的原理是什么 |
| 前后对照 | 使用相同素材和操作，展示旧版与新版的差异；适合时保留截图、录屏或数值 |
| 验证与边界 | 自动测试、实际运行和用户试用分别记录，注明尚未验证的范围 |
| 使用入口 | 从哪个启动入口进入，按什么步骤看到改进 |
| 版本位置 | 分支、提交、阶段标记及 GitHub 链接；核对远端后才写「已上传」 |

可用功能按阶段编号；未通过门槛的算法实验放在「研究补充」，说明发现了什么、为何没有升级。阶段编号不等于整个项目已经完成，也不等于软件正式版本号。

强度连续预览可作为汇报示例：原来拖动后需要等待画面更新；现在先在页面内按相同混合规则响应，再由后端确认。用户已反馈「能连续更新，比较跟手」。该反馈只验收这一操作，不能推广为所有微调控件和所有素材都已流畅。

## 每块内容怎么演示

### 阶段1：参考风格迁移

展示同一目标换参考后的差异，说明模型会依据目标画面产生空间颜色变换。对照原图、旧全局和新版；不要只选好图，保留强青色参考迁移不足等失败例。

核心依据：[训练](research/2026-11-13-multiref-study.md)、[独立32图及限制](research/2026-11-13-multiref-independent.md)。这里不是恢复剪映全部原生算法，也不是已经理解参考图的人物／背景语义。

### 阶段2：视频平滑

展示同一运动短片的未平滑／平滑结果，解释只让调色参数随时间更平稳，不做图像帧混合。并列背景变化曲线、已知平移及硬切检查。

数字来自单条完整素材与固定评价区，不能推广为所有视频都不闪烁；平滑有响应滞后，切镜检测也有边界。依据仍见[独立图和视频记录](research/2026-11-13-multiref-independent.md)。

### 阶段3：能用的软件

双击`00-从这里开始/13-打开自适应调色新版.cmd`，用一张参考及目标图片／短视频演示分析、强度、手动微调和导出，再关闭重开观察工程恢复。12号旧模型入口保留作对照。

说明图片保留原尺寸、视频30fps并保留可用音轨；4K导出仍是离线处理，普通CUBE不能表达空间结果。测试范围见[新版工作台](research/2026-11-13-multiref-workbench.md)。

### 阶段4：连续拖动

先保持基础／HSL／曲线为默认值，连续拖动强度，再关闭克隆比较原色。解释先用已经验证过的像素在页面内响应，后台仍按相同算法确认，不因提速取消素材校验。

用户在本机试用后确认“能连续更新，比较跟手”。这是实际体验反馈，不是自动测得的浏览器帧率。非默认微调仍由后端精确计算，不能说所有控件都已即时化。数学、状态及导出依据见[连续预览记录](research/2026-11-13-strength-preview.md)。

### 阶段5：切镜后不沿用上一镜头的颜色

展示同一低反差切镜边界的原／新平滑对照，再播放同镜运动控制。说明只在判断发生较大画面变化时重置网格，调色模型和正常运动的平滑效果保持原样。不要将10处受控边界推广为所有自然切镜；详见[低反差切镜记录](research/2026-11-14-scene-cuts.md)。

### 阶段6：带微调也能先显示当前参数

演示基础、HSL、曲线逐步叠加后拖动：先显示较小的本地线程预览，后端匹配当前设置时恢复清晰结果。说明数值对照通过、导出保持不变；本次没有浏览器实际拖动测量，不能把线程耗时当成显示延迟。详见[手动微调预览](research/2026-11-14-manual-preview.md)。

## 研究补充：有贡献但未通过的联合颜色分布

2026-11-14完成当前模型的明暗关系诊断、两臂同预算训练和消融。候选对当前模型平均RGB误差改善5.92%，但对普通续训仅改善2.18%，亮度与明暗关系门槛未过，未接入产品；阶段6仍是最新可用功能。汇报时可说明如何发现问题、验证信息来源并拒绝不充分的升级，详见[研究记录](research/2026-11-14-pairwise-study.md)。

## 研究补充：关系训练的取舍

2026-11-14完成固定目标明暗权重的关系训练对照。约束使饱和度代理变化误差比控制改善9.52%，但RGB均值反而差0.65%，亮度与参考响应未同时改善，拒绝升级。保留训练前L1梯度数值失败及修复、180项检查和全部输出审计；不计为新产品阶段。详见[关系训练记录](research/2026-11-14-tone-relations-study.md)。

## 研究补充：变换容量与风格推断

2026-11-14 完成 GT 辅助跨块容量审计及全局输出同预算对照。固定 guide 全局场在 54/64 开发例中拟合 MAE≤3，但实际预测候选相对控制仅改善 0.66%，参考响应和明暗／饱和度完整门槛失败，未升级 13 号。拟合是使用 GT 的诊断，不能当作产品效果；详见[容量与推断记录](research/2026-11-14-capacity-global-grid-study.md)。

## 研究补充：参考原图诊断与训练增强

2026-11-14 完成 75 条训练配对的额外原图诊断，以及 1024 条受控参考生成和同预算训练。额外信息下 guide 迁移均值 5.83522，但实际增强候选相对控制 RGB 误差差 1.53%，参考响应与亮度退化；不升级 13 号。所选三套输出全部指标从图片重算，198 项测试通过。方法、失败例和限制见[参考监督记录](research/2026-11-14-reference-supervision-study.md)。

## 后续每次提交都按这个格式补充

1. **问题**：用户在哪个操作中遇到什么现象。
2. **方法**：改动了哪个环节，为什么这样处理。
3. **效果**：用同样素材和操作展示前后差异。
4. **验证**：自动检查、运行记录、用户反馈分别列出。
5. **限制**：尚未验证或仍失败的范围；下一步解决什么。
6. **版本**：记录功能提交与阶段标记，推送后核对远端，不把本地提交写成已上传。
