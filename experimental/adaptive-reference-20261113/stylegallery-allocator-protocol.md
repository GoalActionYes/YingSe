# FP32准备转FP16后的显存缓存测量

唯一问题：原整图执行的加载／准备历史是否留下较多空闲CUDA缓存，且清理这些缓存能否在保持单步数值精确一致的条件下释放驱动可用显存？当前没有优化阶段allocated/reserved测量，不能预先当作超时根因。

只读已有固定模型与22927自有缓存，无新照片、GT、优化器更新或150步输出。按原GPU FP32逐组件加载，构造同一作者管线；用真实64×64 latent做一次FP32 UNet和VAE前向模拟部分准备历史，再按作者init转FP16。它不包含完整深度／聚类准备，不冒充原整条链的复现。

严格确定性上下文不变。记录加载后、FP32前向后、FP16转换后、每个单步前后的allocated、reserved、驱动free和CPU可用内存。固定同一首个t、空文本、已有C15归一化及排序构造的区域配对、缩放1，运行未清理A、未清理B、清理空闲缓存C三个相同单步。B用于区分预热与清理影响；单次耗时只描述，不作为稳定性能验收。

要求三个损失／输入梯度逐值一致、模型state前后相同；C清理前后reserved至少下降256MiB且allocated不变，才支持一次后续整图执行适配。否则停止缓存假设，不凭计时偶然变化重跑150步。清理使用gc.collect与torch.cuda.empty_cache，不清活张量，不换模型／精度／步数／seed，不将数据转CPU卸载。

预算一次模型加载、两次FP32模拟前向、三个单步，总180秒；首次异常保留状态，不放宽数值条件或资源阈值。不输出新的画质候选，不改变旧桥接失败结论。
