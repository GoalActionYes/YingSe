# PPR监督候选与已消费TST家族的组级排除

问题：537个文档身份候选指向的PPR拍摄组，是否与已消费开发／评估素材的文档来源重叠？本轮只作保守数据排除，不训练、不修改旧划分、不下载照片或读取新评价像素。

绑定旧coverage-v2 manifest的542项heldout注册记录、完整TST索引及上一轮ppr-image-link-v2身份结果。heldout只是历史目录名称，这542项已用于研发；其中可能有GT，本轮只读取它们的元数据，绝不作为模型输入。

先逐项定位原件并核对原SHA。再按完整索引中已核验的原片家族约定，为这些路径寻找唯一原始content路径；仅检查已在本机且有固定输入manifest身份的原件，不新下载。找不到、缺登记或SHA不一致分别记录或停止，不能凭文件名数字猜PPR编号。

复用上一轮白名单标识匹配：原始／专家A XMP只在内存构造关联，标识不落盘。多个命中取交集；无法唯一关联与多候选都保留。对每个非空候选集合，所有PPR组都进入保守排除集合，不从歧义候选中挑选一个；若标识互相冲突，则将命中集合的并集作为可能组保守排除。所有542项及衍生家族查询均须有状态，不因未匹配而删除。

对旧537个唯一训练候选，用PPR组号与排除集合求交，保存应暂不用于新专家监督的路径及组；其他记“本次已知排除后暂余”，不叫独立或训练资格已通过。来源相同但组内照片不同也排除。报告未解析比例；它意味着仍有未知重叠风险，不得将零已知交集当成完整隔离。

PNG／JPEG／TIFF的像素load全部加拒绝守卫；元数据提取复用已核验版本，分组／集合计算另行核对。CPU180秒、无网络或新资产、原件只读。原始源／参数／GT像素不输出。成功标准是完整的已知排除与未知项报告，不是必须找到或排除某个数量。
