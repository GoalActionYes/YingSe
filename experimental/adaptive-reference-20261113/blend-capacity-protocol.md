# Fixed byte-output convex-blend capacity diagnostic

Question: can varying the share of existing C10 appearance output correct failures without sacrificing reference response? This uses GT deliberately as an offline oracle, never an inference algorithm, release candidate or independent evaluation. No model learning/updates/new pixels/app change. Current13/stage6 remains usable.

Use exactly the consumed64 real development rows (32targets x2references). Endpoint A is current13 rendered RGB (C10 run baseline-current), B is completed C10 appearance-pairwise-replica-v1 selectedepoch7. Verify original training/config/source/baseline+selected scores/weights, all64 endpoint PNG and GT prepared hashes. C10 is fixed, do not substitute the latest contrastive model or compare endpoint candidates after scores. No new validation/reserved allocation, no scene/quality exclusions.

Discrete shares k=0..100, denominator100. Blend8-bit decoded outputs AFTER their existing rendering: numerator=(100-k)*A+k*B in int32, exact nearest-even integer rounding via quotient/remainder. This defines a byte-domain diagnostic, not interpolation of raw grids/floating outputs or the app's target-to-result strength. Same A/B pixels yield exact endpoints and no synthesized detail, but future native blending would need its own consistency check. Ordinary CUBE cannot represent these spatial transforms.

For each case retain101 RGB MAEs toGT, select earliest minimum share independently, save selected PNG. Also select a single global earliest-minimum meanRGB share acrossall64, save all64 PNG. Always report both oracle procedures and unchanged endpoints, full paired/tone scores and unchanged response_development_gate(current13,oracle,C10). These gates are descriptive, never permission to allocate fresh data or promote a GT-dependent procedure. No casewise override based on tone/delta scores. Retain all failures and selected shares; inspect fixedfirst2/allremainingsevere/maxgain/maxregression.

Per-case RGB oracle is a lower bound only for RGB error among these101 byte blends. It is not a joint optimum for reference-delta/tone gates, a bound over continuous shares/raw-grid mixing, proof a GT-free predictor can learn the shares, or proof no other algorithm can solve a failed case. Single-global oracle uses all developmentGT and is not a learned deployable baseline. Improvement could be simple damping/ensembling, not understanding style or semantics.

Necessary research-value checks: if per-case oracle cannot reach original C10-relative RGB mean>=3% and improved>=36/64, a predictor restricted to this exact101-way convex family cannot meet those RGB checks here. Otherwise this only motivates investigating learnability; even all descriptive gates passing must not be called product success. No relaxing response/brightness/severe checks or selecting a different oracle objective after results.

Unit tests first: endpoints/identical images, exact-half rounding (0,1->0;1,2->2), signed-safe MAE, known optimal interior share, earliest tie, invalid shape/dtype/share. Freeze source/config/asset hashes before scoring, keep numerical101-score curves and local PNGs, full source+score recomputation audit. Verify no files or weights changed. Code/protocol/aggregate numbers only to Git; no photos/GT/weights/features/environments/sessions. Academic noncommercial scope.
