# 参考背景诊断第二轮：匹配模型亮度定义并避免裁切

在 v1 全部结果与干扰发现之后冻结，运行前不读取 v2 输出。沿用 `background-intervention-protocol.md` 的六对开发输入、保护区、覆盖率、产品路径、默认 80、区域统计、描述性阈值与 144 次推理预算。保留 v1，不以 v2 替换或重新解释它。

唯一修订是构造更严格的色度干预：模型亮度系数固定 `[0.2126,0.7152,0.0722]`，位移 `d=[-24,24*(0.2126+0.0722)/0.7152,-24]`。每个参考像素按原 RGB 求正反方向共同可用的对称色域比例 `s=min(1,min_c(min(rgb_c,255-rgb_c)/abs(d_c)))`。背景改动为 `±d*s*原协议背景权重`，整图正反控制为 `±d*s`。一次量化到 RGB8，不允许原始浮点值超出色域，不允许通过逐像素改变位移方向来求等亮。

该比例会降低饱和或接近端点像素的干预，需报告有效幅度、比例均值、零比例像素及参考 Y／Cb／Cr 实际变化，不能与 v1 干预强度直接比优劣。全图去饱和控制亦使用模型亮度定义，恒等、重跑及对比度不变。所有背景干预人物像素必须完全一致。

数值有效性条件：量化前每像素模型 Y 差≤1e-10，所有 RGB 均在色域；RGB8 量化后每像素模型 Y 差≤0.500001 个码值。报告实际最大值与均值。若失败，停止原因推导，保留失败后修正工具，不放宽数值界限。正反与覆盖率分别保存所有结果，人物、中性色代理和全图统计沿用 v1，新增模型亮度统计避免混淆。

先测试黑白／饱和色／中灰的对称色域约束、人物保护、正反方向及量化亮度界，再执行新输出目录。推理重复项须通过独立缓存重新分析。无训练、无产品修复、无更换权重；只有实际结果与数值控制同时有效才讨论色度响应。零响应也不证明风格正确。人工蒙版不进入产品推理，独立数据不消费，照片、蒙版与输出不上传。
