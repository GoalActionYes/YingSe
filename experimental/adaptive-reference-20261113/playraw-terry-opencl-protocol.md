# 验证 GPU 能否保留 Terry 暖墙编辑的原始配置

需要一组可追溯的实拍局部暖色作为后续开发正例。Terry Pinfold 的同一张混光 RAW 有暖墙编辑及手绘蒙版，作者说明桌面应尽量保持，部分肤色也在操作范围内。已有 Windows 5.0.0 的原片和关闭侧车都在 CPU 去马赛克处失败，原作者侧车与日志中的 Markesteijn 1-pass 一致。5.0.0 源码有同一方法的 OpenCL 分支。本轮只改变渲染后端，固定既有官方程序和原片、作者设置、1024 长边、全质量和 8 位 sRGB TIFF。零下载，GPU 仅出图，机器时间最多 10 分钟。预计从核验到记录用时 25–45 分钟。[旧诊断](../../docs/research/2026-11-24-terry-wall-switch.md) · [同版本去马赛克源码](https://github.com/darktable-org/darktable/blob/release-5.0.0/src/iop/demosaic.c)

在研究目录用隔离配置、缓存和数据库。沿用按字节核验输入与已有 Color Zones 关闭函数。先读原失败日志和作者方法编号，再执行 GPU 关闭态。只有退出成功、获得有效 RGB TIFF、日志证明去马赛克确实在 OpenCL 设备执行，才进入预登记。若 OpenCL 不可用或回退 CPU，存在原来的崩溃或导出不完整，保留实际状态并停止此次后端方案。其他模块自动回 CPU 的情况记录，不能称为全 GPU。

在看开态前，从关闭图登记远处暖墙、桌面和脸颊的框以及关闭图像素哈希。随后使用同一后端再导出另一份关闭与两份开启，开启保留原作者侧车并索取蒙版。所有导出核对日志中的原尺寸去马赛克完成和实际设备，记录共享模块是否改变 CPU 或 OpenCL 执行路径。隔离配置按次建立，允许复用本次首个导出的设备内核缓存。沿用之前的资格线。暖墙红蓝半差中位至少 +2 RGB8，桌面绝对色度变化 P95 不超过 1.5，整图新增端点像素不超过 2%，两个状态重复导出最大差不超过 1 RGB8。报告桌面和脸颊的色度、亮度、RGB 变化及蒙版权重。两态同尺寸、RGB8 及实质一样的 sRGB ICC，核对蒙版标签并要求重复蒙版完全一致。

若满足，按既有规则用两版工作台导出同一原片目标的关闭、开启参考，强度 80%，暖墙使用原颜色误差、期望成片误差与投影 0.75–1.25。桌面仍按原颜色误差、期望成片误差和响应误差 ≤3 RGB8，脸颊保留实测。工作台成片与离线答案区分。此来源只有一档已核实实拍灯光。它能增加一组外部作者的真实暖墙设置及桌面对照，补充已有的项目自定义局部暖色，归入开发正例。跨来源四格、训练及正式独立验收标准照旧。原片、侧车、蒙版、生成图和运行环境留本机。
