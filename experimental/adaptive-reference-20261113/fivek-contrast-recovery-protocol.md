# 核对 FiveK 对比度历史能否恢复原始像素

固定上一轮唯一匹配的两个原文件与同一起止值的 `Contrast +13` 步骤。按已冻结的原文件抽样定位，用图像索引和历史索引双重核对，不追加新照片或编辑样本。追溯原片文件、虚拟副本与当前设置指针；用完整字面量比较当前设置、历史末条与两个已知状态。只在本机保存状态与原片路径，公开的数值摘要不包含图像键、拍摄日期、路径原值或其他作者信息。

查证官方单图目录中的原片与对应专家最终 TIFF 是否确实发布，区分原片、最终状态与中间状态。若原片条目、专家输出和旧处理版本都能核实，检查现有环境能否使用同一旧处理流程逐状态渲染；不安装付费软件、不下载整包。也核对官方归档预览目录头，判断是否披露了能关联中间历史的有效索引。目录访问和源数据头预算合计 512 KiB，不读中间预览的图片内容。

如果缺原渲染器或任一状态没有可信像素，停在可复原性，不用自定义曲线、伽马或最终导出代替历史。在可确认的情况下保留本机原始设置包和精确重放条件。只有已知与原软件状态对应、色彩管理一致且通过两端对齐，才进入明暗迁移对照。本轮不读取独立评估样本、不改变模型。

如果在归档预览目录头遇到独立 SQLite 索引，索引本身可在原预算内完整读取时，核查同一图像键下是否同时能匹配编辑前后的设置摘要。匹配前后需要同一图像，以及两个不同的精确设置标识。若索引只能核实当前状态，或摘要方案无法对齐，明确区分并保留索引覆盖证据。不读取任何 `.lrprev` 文件的数据体。
