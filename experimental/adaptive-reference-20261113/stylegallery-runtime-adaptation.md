# StyleGallery本机执行适配：运行前冻结

原算法配置继续遵循stylegallery-screen-protocol.md，不改变分区、深度模型、匹配规则、损失、150次优化或随机种子。前8条均为不同内容的style0，只能检查严重退化必要条件，不能报告完整32组参考响应。

标准单对demo先以FP32处理分区／匹配，style_transfer内部按作者默认mixed_precision=fp16转换并优化。不能直接全程FP16加载，因为作者匹配函数内部新建FP32 Transformer；本轮保留这两个阶段的原有精度。

为避免整条FP32管线先在CPU驻留，使用同版本Diffusers／Transformers的low_cpu_mem_usage和单GPU device_map逐组件加载原FP32 safetensors，再构造同一作者StyleGallery。检查每个模型state的键、形状和每项值与原safetensors严格相同，只允许CLIP非持久position_ids缓冲不参与比较；不使用量化、FP16权重副本或其他底模。调度器、分词器和预处理仍取同一固定目录。此检查覆盖初始权重身份，不是与另一硬件的完整原生推理等价验证。

首次v1核验器遗漏了官方旧VAE注意力键转换，在推理前停止，无输出。v2对键名映射调用已固定Diffusers的同一_fix_state_dict_keys_on_load，映射值保存原始safetensors键，不修改或复制参数值；要求无键丢失／合并，再逐项核对原文件张量。真实VAE头部和meta模型测试必须覆盖16项旧query/key/value/proj_attn到新to_q/to_k/to_v/to_out.0键及全部形状。保留v1失败目录，不将兼容修正当作画质实验重试。

v2实际核验196／686／248项主组件state并进入深度分区，随后作者日志中的U+26A0警告符号遇到Windows GBK流而中断，未生成调色输出。v3只对自有子进程设置PYTHONUTF8=1、PYTHONIOENCODING=utf-8，不修改作者日志或数学实现；保留v2目录，进程终态核实后才启动v3。

每对在独立子进程从相同原始权重开始，防止上一对style_transfer转成FP16或挂钩后污染下一对的FP32特征准备。作者相对模型路径通过子进程cwd指向固定源码目录；内容／参考和缓存均位于本次自有输出目录。离线环境禁止意外下载。没有人工蒙版目录。

分区匹配使用作者加速demo已有的inference_mode上下文，完成后递归clone结果张量为普通张量，以便后续原生优化安全使用常量。clone不改变值。目标图latent优化保留梯度，模型参数在作者init中冻结；不将每图latent优化称为新模型训练。

外层进程每个子进程最多600秒，包括加载／准备／推理，8对总时间最多2700秒；超时只终止该次自有子进程，保留日志和状态，不动其他程序。首次兼容、硬件或数值失败时停止自动后续子进程，先查具体错误，不静默更改配置继续跑。作者输出用原torchvision save_image保存512图，再按协议缩为256离线评分。

首例输出前不宣称可运行或画质收益。若工程检查失败，不将其计为画质退化；若实际评分发现至少3例严重退化，则停止默认路线，不另换配方。
