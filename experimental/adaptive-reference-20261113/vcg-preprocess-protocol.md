# VideoColorGrading：分开核查真实预处理和模型资源

已有生成色表的 AceTone 未通过真人方向。另一公开方法使用目标和参考差异条件及扩散色表，先做 Monge–Kantorovitch 颜色预处理，也提供 ncc 跳过选项。当前只回答标准预处理会向后续色表阶段带入多大误差，以及能否在本机取得完整模型所需的核验信息。不把阶段结果当作完整方法。

固定作者提交 9d58052bd70eb68ed684003619e62795825f346d，仅获取依赖文件 utils/util.py。直接执行其中三个未改动的预处理函数，参考按原 CLI 的 512 方图，单帧目标，原片 80% 输出。固定 01 ← 02、02 ← 01 两个开发方向，分别使用冷暖参考和风格开关，将默认预处理与 ncc 逐像素直通比较，采用既有整图、双颊和双白幕门槛。检查 ncc 逐像素保持，实际预处理 PNG 两遍各 ≤60 秒。文件和样片保留本机。

以 HTTP Range 在转包固定版本只读首 MiB 并核对响应。完整权重不写盘。依据模型卡 LFS 标识、头部四组件、每组件张量存储量、运行依赖和本机内存登记后续路线。如果有串色，仅记录为生成色表必须抵消的初始误差。完整模型通过或失败均留待以后从真实模型成片判断。
