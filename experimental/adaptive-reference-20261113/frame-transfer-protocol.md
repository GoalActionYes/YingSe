# Frozen frame-resident RGB8 render experiment

Goal: reduce host/device synchronization in the existing full-strength renderer without changing its model, sampling, guide, resolution, float32 operations, 128-row bands or output bytes. This is performance work, not improved semantic/style inference or a declaration of full goal completion.

Current path uploads and downloads each128-row band and synchronously checks finite z/raw values perband. Candidate uploads one completeRGB8frame, keeps the same perband float32 guide/grid/coefficient computation, and fills a complete deviceRGB8frame. Check shape metadata immediately. Compute per-element finite flags before any guide coordinate creation/quantization; replace nonfinite guide/raw elements by finitezero on device and retain a frame-level invalid flag. At end, any invalid flag raises ValueError and no image escapes; otherwise download oneRGB8frame. This changes error detection synchronization, not acceptance: nonfinite results are always rejected before return and are never directly cast to bytes. Never use asynchronous device asserts that poison the CUDA context. Additional twoRGB8 device frames are bounded by image size; keepbandwork bounded. No half precision, resize, skipframe or torchcompile.

First implement separately, no product code changes. Unit checks compare existingbyte_output onCPU fakeengines across band sizes, odd/small/noncontiguous images, empty/invalidchunk rejection, deliberate nonfinite guide/raw in early and late bands, and finite-or-zero invalid-element sanitation before quantization. Zero/partialstrength product paths stay unchanged if laterintegrated.

Measure actual frozen current13 and App8 checkpoints on the same6 consumed images/sizes as stage9:256²,640x360,1920x1080,1917x1081,1080x1920,2160x3840. Warm each method, alternate old/candidate order6times. Verify every output pixel exact vs stage9, record finite failures, median/alltimings, device peakmemory, separately analysis time and currentGPUidentity. Reject if any outputdiff or faultacceptance; integration justified only if1920x1080 and1080x1920 medians improve>=15% and4K doesnotregress>5%, peakallocated remains<2GiB in this standalone process. Smallsizes reported evenifworse. This is not a multiimagequalitystudy or endtoend30fpsacceptance; no timing while unrelatedtestjobsrun.

After pass, bounded integration needs regressiontests and realHTTPPNG/video/audio/strength/manual/cancelchecks against retained prior output hashes. No deployment or newrelease claim based on standalone timings. Product engine identity must invalidate changed source; stablemain1.3 stays unchanged.
